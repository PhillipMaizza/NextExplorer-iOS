# mTLS test lab

A throwaway setup for testing client certificate (mTLS) sign in without a real mTLS server.
Nothing here is a secret: every key is generated locally into `out/`, which is gitignored.

## 1. Generate certificates

```bash
Scripts/mtls/certs.sh            # first time
Scripts/mtls/certs.sh --force    # regenerate
EXTRA_IPS="192.168.1.187" Scripts/mtls/certs.sh --force   # also cover another host
```

`out/` then holds:

| File | Use |
| --- | --- |
| `ca.pem` | The dev CA. Trust it on the simulator or Mac so the server certificate is accepted. Name constrained to localhost, 127.0.0.1, this Mac's LAN IP and `EXTRA_IPS`, so it can't vouch for anything else. |
| `client.p12` | A valid client identity (modern AES encryption). Password `nextexplorer`. |
| `client-legacy.p12` | The same identity in the legacy 3DES format older tools produce. |
| `rogue-client.p12` | Signed by a CA the server does not trust: exercises "certificate refused". |

## 2. Run a gateway

Local, in front of the public demo server:

```bash
node Scripts/mtls/proxy.mjs                                   # https://localhost:8443, certificate required
node Scripts/mtls/proxy.mjs https://nextexplorer.phillipmaizza.com 8443 optional
node Scripts/mtls/proxy.mjs https://nextexplorer.phillipmaizza.com 8443 nginx   # nginx style 400 pages
HOST=0.0.0.0 node Scripts/mtls/proxy.mjs   # reachable from a phone on the LAN too
```

It listens on this Mac only by default, so nobody else on the network reaches the demo through it.

Homelab: `https://192.168.1.187:3662` is a Caddy gateway (`client_auth require_and_verify`) in
front of the demo instance, LAN only. Its certificates live in `/srv/nextexplorer-mtls/certs`
on the Docker VM and come from this script with `EXTRA_IPS="192.168.1.187"`.

## 3. Trust the CA

Simulator (QA sim):

```bash
xcrun simctl keychain C3D0AF54-16CD-407B-9E07-FBBE7B7D4CE7 add-root-cert Scripts/mtls/out/ca.pem
```

Mac: open `ca.pem` in Keychain Access, set it to Always Trust, and delete it when done.

iPhone: AirDrop `ca.pem`, install the profile, then enable it under Settings, General, About,
Certificate Trust Settings.

## 4. Sign in

1. Enter `https://localhost:8443` (simulator) or `https://192.168.1.187:3662` (homelab).
2. Test Connection fails with "This server asks for a client certificate" and offers Add Certificate.
3. Pick `client.p12` (drop it into the Files app first on the simulator), enter `nextexplorer`.
4. The connection test reruns on its own and continues to sign in.

Check with curl:

```bash
cd Scripts/mtls/out
curl --cacert ca.pem https://localhost:8443/api/auth/status                                  # handshake refused
curl --cacert ca.pem --cert client.pem --key client.key https://localhost:8443/api/auth/status
```

The automated suite does not need any of this: `ClientCertificateTests` in NetworkClient runs a
real TLS listener in process with fixtures generated by `certs.sh` (`DAYS=7300 LAN_IP=none`).
